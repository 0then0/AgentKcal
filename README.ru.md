AgentKcal объединяет данные об использовании AI-агентов в локальном журнале. Он показывает потреблённые токены, оценивает энергозатраты в ватт-часах и килокалориях по настраиваемому сценарию и сравнивает эту энергию с привычными продуктами.

Для ежедневной работы доступны CLI и компактные сводки внутри агентов, для истории и сравнений — локальный dashboard. Записи хранятся в SQLite; само приложение не делает исходящих сетевых запросов.

**Энергозатраты рассчитываются по допущениям, а не измеряются.** Килокалории выражают эквивалент той же физической энергии, а не съеденную пищу или калории, потраченные человеком. [Как устроена оценка](docs/methodology.md).

## Быстрый старт

Нужны **Node.js 24.12+** и npm.

```sh
git clone https://github.com/0then0/AgentKcal.git
cd AgentKcal
npm ci
npm run build
npm run demo
```

Откройте **http://127.0.0.1:8765**. Демо использует временную базу, не читает ваши журналы и удаляет свои данные при штатном завершении. Для остановки сервера нажмите **Ctrl+C**.

Примеры ниже запускаются прямо из репозитория. CLI также можно [установить из собранного пакета](docs/cli.md#install-the-cli).

## Учёт своих данных

```sh
# Создать конфигурацию и посмотреть доступные адаптеры.
node dist/cli.js init
node dist/cli.js agents

# Импортировать локальные журналы и получить сводку за сегодня по UTC.
node dist/cli.js sync
node dist/cli.js status --language ru

# Посмотреть другой период или открыть dashboard.
node dist/cli.js summary --days 30
node dist/cli.js serve
```

Импорт можно повторять: неизменившиеся события пропускаются, обновлённые снимки заменяют существующие записи. Кнопка синхронизации в dashboard выполняет тот же импорт. Обычное обновление страницы читает базу без импорта журналов.

Для агентов с экспортами или явно выбранными журналами задач:

```sh
node dist/cli.js sync --adapter cursor --path ./cursor-usage.csv
node dist/cli.js sync --adapter opencode --path ./session-export.json
node dist/cli.js sync --adapter cline --path /path/to/tasks
```

Изолированный пример, который не использует ваш основной журнал:

```sh
node dist/cli.js --data-dir ./local-data sync --adapter generic --path examples/usage.jsonl
node dist/cli.js --data-dir ./local-data summary --days 0
```

Все команды, фильтры, форматы экспорта и коды завершения описаны в [справочнике CLI](docs/cli.md).

## Поддерживаемые агенты

- **Claude Code:** локальные проектные JSONL, включая вложенные журналы субагентов. Учитывается `CLAUDE_CONFIG_DIR`.
- **Codex:** rollout JSONL из каталогов сессий и архивных сессий. Учитывается `CODEX_HOME`.
- **Gemini CLI:** локальные JSON и JSONL сессий в `~/.gemini/tmp/`.
- **Cursor:** Usage CSV с необходимыми колонками счётчиков токенов.
- **OpenCode:** JSON-экспорты сессий с классическими или плоскими сообщениями.
- **Cline:** явно выбранные журналы задач `ui_messages.json`.
- **Другие агенты:** нормализованный JSONL через адаптер `generic` или отдельный TypeScript-адаптер.

Поддержка зависит от формата источника и наличия счётчиков. Подключение MCP само по себе не добавляет недостающую телеметрию. [Форматы, стандартные пути и правила учёта](docs/adapters.md).

## Сводки внутри агентов

```sh
node dist/cli.js status --agent codex --sync --language ru
node dist/cli.js integration --agent claude --language ru
node dist/cli.js integration --agent codex
```

- **Claude Code:** постоянная нативная строка состояния показывает токены текущей сессии и приблизительные Wh/ккал без вызова модели.
- **Codex, Gemini CLI, Cursor, OpenCode и Cline:** локальный stdio MCP-сервер позволяет получать компактные сводки по запросу в диалоге. Для удобного вызова доступны skill и шаблоны команд.

Команда `integration` печатает настройки для добавления в конфигурацию агента, не изменяя её. Инструменты MCP разделены: `get_usage` читает сводку, `sync_usage` обновляет источники. Чтение сводки не запускает скрытый импорт.

Результат MCP попадает в контекст агента и может передаваться его провайдеру модели. Сама база остаётся локальной. [Настройка интеграций](docs/integrations.md).

## Языки, темы и сравнения с продуктами

Dashboard и компактные сводки поддерживают **английский, русский, испанский, немецкий, французский, японский и бразильский португальский**. Языковые коды: `en`, `ru`, `es`, `de`, `fr`, `ja`, `pt-BR`.

При первом посещении выбирается поддерживаемый язык браузера; изменить его можно в верхней панели. Форматы чисел, дат и названий порций зависят от языка. Идентификаторы агентов и моделей, пользовательские названия сценариев, диагностика источников и поля экспортов сохраняют исходный вид. Общая справка CLI и полные текстовые отчёты доступны на английском.

Доступны темы **Системная**, **Светлая** и **Тёмная**. Системная реагирует на изменения оформления ОС. Язык, тема и выбранный продукт сохраняются в localStorage браузера и синхронизируются между вкладками одного локального адреса.

Блок сравнения переводит оценку в ккал в условное количество **гречки, пельменей, хлеба, молока, бананов, риса, кукурузы или картофеля**. Для каждого продукта указаны масса порции и её калорийность. Пять иллюстраций показывают целые или частичные порции; дополнительные учитываются в числовой отметке. Полоса показывает долю следующей порции. Это сравнение энергий, а не цель питания и не запись о съеденной пище. [Порции, формулы и источники](docs/methodology.md#food-comparisons).

## Расчёт и точность

Адаптеры приводят исходные счётчики к непересекающимся категориям:

```text
input + output + cache_read + cache_write + reasoning = total_tokens
```

Для каждой категории задаётся расход Wh на миллион токенов. Сумма умножается на PUE — коэффициент дополнительных энергозатрат дата-центра:

```text
Wh = PUE × Σ(токены_категории × Wh_на_миллион / 1 000 000)
kcal = Wh × 3 600 / 4 184
```

Начальные коэффициенты: **100 для входа, 400 для выхода, 10 для чтения кэша, 125 для записи кэша и 400 для размышлений**, при **PUE 1,2**. Это условные допущения для всех моделей, а не измеренные показатели эффективности поставщиков. При переданных времени и мощности GPU формула `PUE × gpu_seconds × gpu_watts / 3 600` заменяет оценку по токенам для того же события.

Диапазон **0,1×–10×** показывает чувствительность к допущениям. Это не статистический доверительный интервал; реальный расход может оказаться за его пределами. Обучение, производство оборудования, сеть, ваше устройство и неотражённая работа агентов не учитываются. [Методика и калибровка](docs/methodology.md).

## Конфигурация и приватность

Каталог данных выбирается по `--data-dir`, затем `AGENTKCAL_HOME`, затем `$XDG_DATA_HOME/agentkcal` или `~/.local/share/agentkcal`.

`init` создаёт `config.json`, не перезаписывая существующий файл. В нём настраиваются пути к источникам и профили моделей. Изменение энергетических параметров пересчитывает отчёты по исходным счётчикам без повторного импорта. [Справочник конфигурации](docs/configuration.md).

SQLite хранит идентификаторы записей, время UTC, модели, счётчики токенов и необязательную телеметрию GPU. Промпты, ответы, аргументы инструментов и учётные данные не сохраняются. Dashboard слушает `127.0.0.1` и рассчитан на одного пользователя локального компьютера. [Хранение, резервные копии и границы доступа](docs/privacy.md).

## Разработка

Проект использует TypeScript 7, встроенные API SQLite и HTTP в Node.js, HTML и CSS. Зависимостей npm времени выполнения нет. За линтер и форматирование отвечает Biome.

```sh
npm ci
npm run check
npm run typecheck
npm test
npm run test:package
```

Структура проекта, требования к тестам и правила участия описаны в [CONTRIBUTING.md](CONTRIBUTING.md). Dependabot группирует обновления раз в месяц; major-обновления рассматриваются отдельно.

## Состояние проекта

AgentKcal **0.1.x — альфа-версия**. Форматы источников могут меняться. Импорт перечитывает выбранные файлы, отчёты загружают подходящие события в память; большая история требует больше времени и памяти. Удалённые журналы, неполные счётчики, сжатие истории и ответвления сессий влияют на полноту учёта и однозначность идентификаторов. [Известные ограничения](docs/adapters.md#identity-and-completeness).
